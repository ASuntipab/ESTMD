# เกณฑ์ระดับงาน

## เป้าหมาย

เพิ่มหน้าที่ผู้ประเมินเปิดอ่านเกณฑ์ Low, Medium และ High ก่อนหรือระหว่างกรอกประมาณการได้ โดยใช้แนวทางและตัวอย่างจาก `C:\Source\ProjectStandard\Present version 4\data.js` และส่วน Level Definition ใน `index.html` ที่ผู้ใช้ให้เป็นข้อมูลอ้างอิง

## การออกแบบ

- เพิ่มแท็บ “เกณฑ์ระดับงาน” ในชุดแท็บ Standard Matrix และให้ผู้ใช้ที่ล็อกอินทุกคนเห็น
- เพิ่มหน้าอ่านอย่างเดียวที่ `/matrix/criteria`; จำกัดหน้าไว้สำหรับผู้ใช้ที่ผ่านการยืนยันตัวตน
- ใช้รูปแบบ A ที่ผู้ใช้เลือก: เกณฑ์ Low/Medium/High แสดงเป็นคอลัมน์ที่เทียบกันได้ แล้วแสดงตาราง Work Type และ Unit พร้อมเกณฑ์ทั้งสามระดับ
- แสดงคำจำกัดความระดับงานที่จัดกลุ่มตามหัวข้อจาก `LEVEL_DEF` และรายการเฉพาะประเภทงานจาก `WORK_TYPE_LEVELS` ตามไฟล์อ้างอิง รวมหลักตัดสินให้ใช้ระดับสูงสุดของปัจจัยหลัก
- เก็บข้อความเกณฑ์เป็นข้อมูลคงที่แบบมีชนิดในแอป ไม่เพิ่มตารางฐานข้อมูลหรือฟอร์มแก้ไข
- ใช้สีและคอมโพเนนต์เดิมของ Standard Matrix; ตารางเลื่อนได้ในจอแคบและข้อความหลายบรรทัดอ่านได้ครบ

## การไหลของข้อมูลและสิทธิ์

หน้าอ่านข้อมูลคงที่จากโมดูลเกณฑ์ในแอป แล้วแสดงผลผ่าน Server Component หลัง `requireUser()`. ไม่มีการบันทึกหรือเปลี่ยนแปลงโครงการ เมทริกซ์ หรือสูตรประเมิน ค่า MD เดิมยังคำนวณจาก Standard Matrix ตามเดิม

## ขอบเขตที่ไม่รวม

- แก้ไข เพิ่ม หรือลบเกณฑ์ผ่านหน้าเว็บ
- เปลี่ยนวิธีให้ระดับความซับซ้อนหรือสูตรคำนวณ Man-day
- นำ Complexity Rules และเกณฑ์คะแนนอัตโนมัติจากต้นแบบมาใช้

## เกณฑ์ยอมรับ

1. ผู้ใช้ที่ล็อกอินเห็นแท็บและเปิด `/matrix/criteria` ได้; ผู้ใช้ที่ยังไม่ล็อกอินถูกส่งผ่าน flow การยืนยันตัวตนเดิม
2. หน้าแสดงเกณฑ์ทั่วไป, หัวข้อและรายการ Low/Medium/High จาก `LEVEL_DEF`, ตาราง Work Type/Unit จาก `WORK_TYPE_LEVELS`, และหลักการตัดสินระดับสูงสุด
3. เนื้อหาเป็นแบบอ่านอย่างเดียวและรองรับข้อความหลายบรรทัดกับจอแคบ
4. หน้าอื่นและข้อมูล estimate ไม่เปลี่ยนพฤติกรรม

## การตรวจทาน

ก่อนส่งมอบ ให้ตรวจ diff และผลการเปลี่ยนแปลงของหน้า/ข้อมูลตามเกณฑ์ยอมรับ ผู้ใช้ยังไม่ได้ขอให้รันทดสอบอัตโนมัติ จึงไม่กำหนดการเพิ่มหรือรันชุดทดสอบในสเปกนี้
